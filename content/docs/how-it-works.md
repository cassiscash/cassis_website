## The problem

Bitcoin is no longer one network. Lightning channels, Liquid, Arkade, ecash
mints, federations and sidechains each hold liquidity and users, but value
rarely crosses between them. Today that crossing requires a trusted bridge, a
wrapped IOU or an exchange account.

Cassis removes the trust. A payment becomes a **route**: an ordered chain of
**hops**, where each hop is a plain HTLC (hash time-locked contract) on the
layer it lives on.

## The ingredients

Every Cassis payment uses three ingredients:

1. **A secret `R`** &mdash; 32 random bytes generated by the receiver.
2. **Its hash `H`** &mdash; `H = SHA-256(R)`, shared with everyone in the route.
3. **Timeouts** &mdash; each hop's expiry block, strictly decreasing from source
   to destination.

```text
  sender ──HTLC(H, t₀)──▶ hop 1 ──HTLC(H, t₁)──▶ hop 2 ──HTLC(H, t₂)──▶ receiver
                          t₀ > t₁ > t₂
```

Every contract says the same thing, in whatever script language the layer
speaks:

> The receiver of this contract may claim the funds before block `t` by
> revealing a preimage of `H`. After block `t`, the sender may refund.

## The happy path

1. The receiver generates `R` and sends `H` to the sender inside the payment
   request.
2. The sender walks the route and locks the first hop on the source layer.
3. Each intermediary, seeing funds locked for itself downstream, locks its own
   hop upstream &mdash; same `H`, shorter timeout, plus a small fee.
4. The receiver claims the last hop by revealing `R`.
5. Each intermediary learns `R` as its downstream leg settles and uses it to
   claim upstream. The reveal cascades backwards until the sender's leg is
   consumed.

At no point can any party both keep the funds *and* leave the route unsettled:
claiming requires the preimage, and revealing the preimage hands the whole
route its settlement token.

## The failure path

If any hop refuses to lock, or a timeout expires before the preimage arrives,
the route simply unwinds: every locked contract refunds to its sender once its
own expiry passes. Timeouts decreasing along the route guarantee that no
intermediary can be stuck after having paid downstream &mdash; upstream money is
always claimable or refundable *before* downstream obligations expire.

## Where the layers plug in

Cassis does not require anything exotic from a layer. If it can express
"claim with preimage of `H` before `t`, else refund", it can join a route:

| Layer            | HTLC primitive                                |
| ---------------- | --------------------------------------------- |
| Lightning        | BOLT-2 `update_add_htlc`                      |
| Liquid           | `OP_CHECKSIGVERIFY` + `OP_SHA256` + CSV       |
| Arkade           | VTXO script with hash lock + relative lock    |
| Cashu / Fedimint | mint-held HTLC offer against `H`              |
| Rootstock        | Solidity HTLC contract                        |

See [supported layers](@/docs/layers.md) for details on each integration.
