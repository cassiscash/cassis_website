{# ======================== HTLC EXPLANATION ========================= #}

How Cassis works

Routed with hash time-locked contracts

A Cassis payment is a chain of HTLCs sharing one hash. The receiver generates a random secret R and hands the sender its hash H. Every intermediary along the path locks funds against the same H, each with a strictly shorter timeout than the hop before it.

When the receiver claims the final hop by revealing R, the secret propagates upstream hop by hop and every contract settles. If any leg stalls, its timeout expires and funds simply refund. Nobody can take the money and run.

One hash binds the whole route

Every hop references the same H, so claims are cryptographically tied to a single secret.

Timeouts decrease upstream

Each earlier hop has more time than the next, guaranteeing a refund path if the route fails.

Settlement cascades backwards

The preimage reveal lets each hop claim downstream before settling upstream. Atomic by construction.

{# ============================== STEPS ============================== #}

The payment lifecycle

Lock. Route. Settle.

Lock

The sender commits funds on the source layer in an HTLC: the receiver can claim with the secret, the sender refunds after timeout. No custodian, no deposit address.

hash H published refund path set

Route

Routers — swap nodes, mints, federations — extend the chain, each locking funds with the same hash and a shorter timeout, taking a small fee for the hop.

same hash per hop decreasing timeouts

Settle

The receiver reveals the preimage and the route unwinds atomically: every hop claims downstream and settles upstream, or everything refunds. All or nothing, every time.

preimage cascades atomic guarantee
{# ============================ EXAMPLES ============================= #}

Routes across the bitcoin stack

Any source, any destination

Arkade to Fedimint

Arkade → Liquid → Fedimint

An ark sender pays a fedimint user without either touching the mainchain. A liquid swap node bridges the two: it claims the ark HTLC with the preimage and funds a fedimint payout locked to the same hash.

Rootstock to Lightning

Rootstock → Cashu → Lightning

BTC locked on rootstock exits through a cashu mint that issues ecash against the shared hash, then a lightning router settles the final invoice. One secret, three layers, zero trust assumptions beyond the contracts.

Why Cassis

Layers are the future.
Routing is missing.

The bitcoin ecosystem is exploding into layer-specific silos. Cassis is the missing fabric that lets value flow between them while keeping every guarantee on-chain.

Contracts, not reputation

Intermediaries are bound by HTLCs with hard timeouts, not by trust or identity. Cheaters only ever lock up their own funds.

Layer-agnostic by design

Anything that can express a hash lock and a time lock can join a route: channels, sidechains, rollups, mints, federations.

Cheap enough for payments

Routes never touch the base layer individually. Fees are per-hop and competitive, making small and frequent transfers practical.

Bitcoin-only, forever

No new token, no governance, no bridge multisig to pwn. Cassis routes satoshis, and that is all it will ever do.
